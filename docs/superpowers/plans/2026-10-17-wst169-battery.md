# WST169 Phase 2 (Battery) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Touch-LCD-1.69 runs from a 1S LiPo. It latches its own power, the PWR key sleeps, wakes and powers off, it shows the charge, it stays silent, and it cuts itself off before over-discharge.

**Architecture:**
- **Power logic.** The pure parts are in a new hardware-free unit, `firmware/main/pwr_logic.{c,h}`: the key press detector, the charge-percent curve, the cable / no-battery classification and the low-voltage cutoff timer. A host test in `firmware/host_test/` covers them.
- **Battery port.** A new `firmware/main/battery_port_adc.c` implements the whole `battery_port.h` interface for WST169 on top of `pwr_logic`: the ADC on GPIO1, the key on GPIO40, and power-off through SYS_EN on GPIO41. CMake selects it instead of `battery_port_axp2101.c`.
- **main.c.** It gets small `#if CONFIG_POCKET_TANK_WST169` hooks: the early latch, the power-off branch, the PWR wake in the dark, the touch doze and the low-voltage cutoff.

**Tech Stack:** C11, ESP-IDF v5.5.2 (`esp_adc` oneshot + curve-fitting calibration, `driver/gpio`, light sleep), host C tests.

**Spec:** `docs/superpowers/specs/2026-10-17-wst169-battery-design.md` (phase 1: `docs/superpowers/specs/2026-10-17-wst169-port-design.md`, bench log `docs/board-touch-lcd-1.69.md`, `Handoff.md`).

## Review Focus

1. **The board goes dark on battery right after a PWR tap.** The latch must be the first statement of `app_main` and held across panic/`esp_restart` (`gpio_hold_en`). Task 1 checks the order; the battery bench (Task 5) proves it.
2. **The wake press re-sleeps the tank.** The release of the press that woke the dark must not arrive as a fresh short press in the tank loop. The host test in Task 2 covers the detector, and Task 3 owns the dark-loop swallow.
3. **A long press while the screen is dark.** It must power off, not just wake. Task 3.
4. **The low-voltage cutoff fires on the cable.** On a USB cable with no battery the ADC may read noise or 0; that must never power off. The host test in Task 2 and the bench on USB in Task 4 cover it.
5. **Other boards.** No AXP2101 or main.c behaviour may change for non-WST169 builds. Every task runs the builds and check-all.

**Interfaces:**
- Consumes: Task 1's pins and `board_power_release()`.
- Produces (pwr_logic.h):
  ```c
  typedef struct { bool down; bool armed; int64_t since_us; bool long_sent; int pending; } pwr_key_t;
  void pwr_key_init(pwr_key_t *k, bool down_now);          /* down at boot (the power-on press): not armed until released */
  void pwr_key_sample(pwr_key_t *k, bool down, int64_t now_us); /* feeds one sample; queues 1 (short, at release < 1.5 s) or 2 (long, at 1.5 s held) */
  int  pwr_key_take(pwr_key_t *k);                         /* 0 / 1 / 2, then clears */
  void pwr_key_swallow(pwr_key_t *k, bool down_now);       /* drop pending; if down, disarm until released */
  float pwr_pct(int vbat_mv);                              /* 0..1, piecewise Li-ion, 4150 = 1, 3300 = 0, clamped */
  bool pwr_battery_present(int vbat_mv);                   /* 2500..4350 */
  int  pwr_state(bool usb_host, bool rising, int vbat_mv); /* BAT_ON_BATTERY / BAT_CHARGING / BAT_FULL (>= 4150 on the cable) */
  typedef struct { int64_t low_since_us; } pwr_cutoff_t;
  bool pwr_cutoff_due(pwr_cutoff_t *c, bool on_cable, int vbat_mv, int64_t now_us); /* true after 30 s below 3300 off the cable; on the cable or no battery: never, and the timer resets */
  bool pwr_boot_too_low(bool on_cable, int vbat_mv);       /* off the cable and present and < 3200 */
  ```
- Produces (battery_port_adc.c), the whole `battery_port.h`:
  - `init` → true when the ADC is up;
  - `read` → frac / charging, false when no battery;
  - `state`, `vbat_mv` (0 = no battery);
  - `poweroff` → `board_power_release()`, then true;
  - `key_init` / `key_poll`: an `esp_timer` samples GPIO40 every 10 ms into `pwr_key_t`, and `key_poll` returns `pwr_key_take`;
  - `key_trace` logs presses;
  - `battery_port_key_swallow(void)`: new, declared in battery_port.h; on AXP2101 it drains the IRQs;
  - `dump` / `charge_report` log VBAT;
  - `set_rail` / `pin_rail` / `trim_rails` / `set_charge_ma` are no-ops that log "no PMIC";
  - `charge_ma` returns 0.
  - "rising" means VBAT up ≥ 15 mV over a 3-minute window of 1 s cached reads.

  - `pwr_key_swallow` with down=true, then a release, gives nothing;

### Task 3: main.c — power-off, the PWR key in the dark, touch doze, low-voltage cutoff

**Files:**
- Modify: `firmware/main/main.c`
  - `enter_poweroff`: a WST169 branch BEFORE `#ifndef SLEEP_MODE_DEEP`: save, bat_hist, batlog "off", imu/display sleep, `battery_port_poweroff()`, wait 1 s. If still alive (USB), log it and `enter_dark(0, false)`, then return.
  - `enter_dark` / `dark_wait`: on WST169, arm PIN_PWR_KEY as a light-sleep GPIO wake at the active level, only while it reads released; check the key every look, not only on `DARK_SLOW_EVERY`. A short press wakes; a long press calls `enter_poweroff()`. After any wake, `battery_port_key_swallow()` so the wake press's release isn't a new sleep press.
  - The tank loop: on WST169, every 1 s, `pwr_cutoff_due(...)` → `s_sleep_why = "low battery"` and `enter_poweroff()`.
  - Boot: right after `battery_port_init`, `pwr_boot_too_low(...)` → log, then `battery_port_poweroff()` (no screen).
- Modify: `firmware/main/touch_port.h` / `touch_port_ft3168.c`: `void touch_port_doze(bool doze);`. On WST169 it writes 0xFE = doze ? 0 : 1; elsewhere it does nothing. `enter_dark` calls `touch_port_doze(true)` only when the dark will really light-sleep (`light && !usb_serial_jtag_is_connected()`), and `touch_port_doze(false)` at the wake.

**Interfaces:**
- Consumes: `battery_port_key_poll`, `battery_port_key_swallow`, `battery_port_poweroff`, `battery_port_vbat_mv`, `battery_port_state` (Task 2), `pwr_cutoff_due`, `pwr_boot_too_low` (Task 2), `board_power_*` (Task 1).
- Produces: `touch_port_doze(bool)`.
